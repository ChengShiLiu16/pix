重构 $@，严格保持功能不变，只改善代码结构。

重构前必须先完整阅读相关文件，理解现有逻辑。

按以下顺序逐步重构，每步确认不破坏功能：

1. **提取重复代码** — 相同或相似逻辑超过 2 处，提取为独立函数
2. **简化条件逻辑** — 嵌套 if 超过 2 层的，用卫语句/策略模式/查表法简化
3. **缩小函数体** — 超过 30 行的函数，按职责拆分
4. **改善命名** — 变量/函数名不清晰的，改为自描述名称
5. **消除魔法值** — 硬编码的数字/字符串提取为命名常量

约束：
- 不要改变公共 API 和函数签名
- 不要添加新功能
- 不要修改测试用例（重构后现有测试必须全部通过）
- 每步重构后运行项目检查命令验证

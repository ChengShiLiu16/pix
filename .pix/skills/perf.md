分析并优化 $@ 的性能。

**第一步：测量，不要猜测**
- 如果有性能测试/benchmark，先运行获取基线数据
- 如果没有，分析代码识别最可能的瓶颈点

**第二步：分析**
检查以下常见问题：
- 🔴 O(n²) 或更高复杂度 → 可否降为 O(n) 或 O(n log n)？
- 🔴 不必要的全量计算 → 可否增量/懒加载/缓存？
- 🔴 重复计算相同结果 → 提取为变量/缓存
- 🟡 不必要的数据复制 → 可否引用传递？
- 🟡 频繁 DOM 操作 → 批量更新/虚拟滚动/防抖节流
- 🟡 大量同步 I/O → 异步化/并行化
- 🟢 未使用的导入/变量 → 清理

**第三步：优化**
- 每次只改一处，改完验证
- 记录优化前后的对比数据
- 不要为了微优化牺牲可读性

约束：
- 优化不能改变功能行为
- 优先优化瓶颈（80/20 原则）
- 优化后必须通过现有测试

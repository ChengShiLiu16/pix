逐层解释 $@ 的代码逻辑。

先完整阅读文件，然后按以下结构输出：

**一句话概括** — 这个文件做什么，解决什么问题

**核心数据流** — 数据从哪里来，经过哪些变换，到哪里去（用 → 连接）

**关键函数逐个拆解**：
- 函数名和职责（一句话）
- 输入 → 输出
- 内部核心逻辑（不要逐行翻译，讲清楚"为什么这样做"）
- 和其他函数的调用关系

**设计决策** — 为什么用这种模式/数据结构，而不是另一种

**潜在风险** — 可能出问题的地方、假设条件、未处理的边界

如文件超过 200 行，只解释公开 API 和核心逻辑，跳过纯工具函数。
